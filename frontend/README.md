# 우리집 노트캠 · React 프론트엔드

React 18 + Vite 기반 NoteCam 프론트엔드입니다. 서비스 코드, 자동 검사와 개발용 미리보기를 관리합니다. 의존성 설치와 npm 명령은 `frontend/`에서 실행합니다.

## 실행

```powershell
cd frontend
npm ci
npm run dev
```

기본 접속 주소는 `http://localhost:5173`입니다. 백엔드는 `../aio-03-p1-team2` 저장소의 실행 안내를 따릅니다.

API 기본 주소는 `http://127.0.0.1:8000`입니다. 변경하려면 `frontend/.env`에 아래 값을 설정하고 개발 서버를 다시 실행합니다.

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:8000
```

실제 프론트 주소를 백엔드의 `CORS_ORIGINS`에도 등록해야 합니다. 프론트 환경 변수에는 서버 전용 비밀 키를 넣지 않습니다.

저장소 루트의 `Image/`는 디자인 원본 보관용입니다. 앱은 `frontend/src/assets/`와 `frontend/public/`의 자산을 사용합니다. `node_modules/`와 `dist/`는 설치·빌드 결과이며 Git으로 관리하지 않습니다.

## 코드 배치 기준

- `app`: 여러 기능을 연결하는 앱 구성과 탐색 메뉴. 기능별 API 요청은 여기에 두지 않습니다.
- `features/기능명`: 페이지, 기능 전용 컴포넌트, 상태 관리 훅, API, 스타일을 함께 둡니다.
- `shared`: 여러 기능에서 사용하는 컴포넌트와 통신·상태 처리 도구만 둡니다. 특정 기능을 import하지 않습니다.

페이지는 기능 훅의 상태를 화면 컴포넌트에 전달합니다. API 모듈은 요청 경로와 입력 데이터를 정의합니다. JSON 요청은 `shared/api/client.js`, 파일 업로드·사진 다운로드 등 비전 요청은 `shared/api/request.js`가 처리합니다. API별 취소·재시도 처리는 `useApiResource` 또는 기능 훅에서 관리합니다.

저장 중에는 공통 메뉴와 로그아웃을 비활성화해 진행 중인 작업이 화면 이동으로 끊기는 것을 방지합니다. 화면별 스타일은 해당 기능에, 버튼·페이지 이동 등의 공통 스타일은 `shared/styles`에 둡니다.

현재 메뉴를 다시 클릭하면 `PageRefreshContext`로 재조회합니다. 작성 중인 입력·검색 조건·페이지 위치를 유지하며, 지원하는 목록은 기존 내용을 표시한 채 갱신 상태를 안내합니다. 프로필·실시간 보기 재클릭은 공통 재조회에서 제외합니다. `useApiResource.refresh()`와 화면별 새로고침은 해당 데이터만 다시 조회합니다.

## 현재 기능 범위

| 대상        | 메뉴                | 주요 기능                                                                                      |
| ----------- | ------------------- | ---------------------------------------------------------------------------------------------- |
| 공통        | 나의 프로필         | 닉네임·아바타·Discord 연결 설정                                                                |
| 공통        | 실시간 보기         | 브라우저 카메라 제어·최근 움직임·분석 질문 설정                                                |
| 일반 사용자 | 내 대시보드         | 현재 브라우저의 카메라 상태·최근 최대 20건 분석 현황·확인 필요 기록·처리 대기 피드백·최근 알림 |
| 일반 사용자 | 모니터링현황        | 촬영이 끝난 사건의 사진·분석 결과 조회                                                         |
| 공통        | 고객 피드백         | 제목·내용·번호 검색, 유형·상태 필터, 본인 작성·수정·삭제                                       |
| 관리자      | 운영현황            | 사용자·피드백 통계, 최근 피드백 처리 및 감사 로그 바로가기                                     |
| 관리자      | 카메라 기록         | 다른 사용자의 카메라·사진·분석 이력 조회                                                       |
| 관리자      | 고객 피드백 관리    | 전체/본인 목록 전환·처리 상태 및 관리자 답변 수정                                              |
| 관리자      | 계정 관리·감사 로그 | 계정 권한·활성 상태 수정과 변경 이력 조회                                                      |

프로필에서는 부엉이·라쿤·곰·토끼 아바타를 선택하고 계정 요약과 가입일을 확인할 수 있습니다. 선택한 아바타는 계정별로 현재 브라우저에만 저장되며, 닉네임은 이름 옆 수정 버튼에서 기존 프로필 API로 변경합니다.

로그인하면 홈 화면과 서비스 화면 상단에 선택한 아바타와 닉네임이 표시됩니다. 이를 누르면 프로필 화면으로 이동합니다.

Discord 로그인과 기존 계정 연결, DM 수신 설정·테스트 발송·연결 해제를 제공합니다. 사용 가능 여부는 백엔드 설정에 따르며 준비되지 않은 경우 화면에서 안내합니다. 로그인 연결과 DM 설정은 [Discord 기능 안내](frontend/src/features/discord/README.md)를 참고하세요.

일반 사용자와 관리자 모두 같은 탭에서 새로고침해도 로그인을 복원합니다. `sessionStorage`에 access token과 만료 시각만 보관하고, 앱 시작 시 `/api/auth/me`로 사용자와 권한을 다시 확인한 뒤 서비스 화면을 표시합니다. 비밀번호·refresh token·사용자 권한은 저장하지 않습니다. 로그아웃·토큰 만료·인증 실패 시 저장 정보를 삭제합니다. 서버 연결 실패 시에는 토큰을 보존하고 재시도 또는 다시 로그인을 선택할 수 있습니다. 저장소 사용이 차단된 브라우저에서는 기존 메모리 로그인으로 동작합니다.

탭이 닫히거나 토큰이 만료되면 다시 로그인해야 합니다. 자동 토큰 갱신과 새로고침 전 메뉴·카메라 실행 상태 복원은 포함하지 않습니다.

실시간 보기와 모니터링현황은 로그인 토큰 소유자의 비전 데이터를 사용합니다. 브라우저 카메라 세션을 App에서 공유해 메뉴를 이동해도 녹화를 유지하고 내 대시보드에 현재 카메라 상태를 표시합니다. 소개 홈으로 이동하거나 로그아웃하면 카메라 화면이 해제됩니다. 모션 실행·이벤트·프레임·분석 API는 로그인 상태에서만 호출합니다.

소개 홈의 이미지·영상은 서비스 예시입니다. 홈 화면의 로고는 페이지 전체를 새로고침하고, 서비스 화면의 로고는 소개 홈으로 이동합니다.

관리자 **카메라 기록** 메뉴는 `/api/admin/cameras`로 카메라를 20개씩 조회합니다. 사용자 선택 목록에는 이메일과 사용자 ID를 함께 표시하며, 카메라 목록에도 소유자의 이메일·사용자 ID를 표시합니다. 사용자 정보는 기존 `/api/admin/users`를 페이지별로 조회하고, 사용자 조회가 실패해도 카메라 기록은 계속 볼 수 있습니다. 선택한 카메라의 사건을 최근 최대 100건 조회하고, 사건 상세에서 관리자 전용 사진·분석 API로 촬영 사진과 최종 분석을 확인합니다. 사진 묶음별 자동·수동 Gemini 분석 이력도 최근 최대 100건 조회하며 모델·질문·판정·설명·오류를 확인할 수 있습니다. 조회 전용이며 카메라 제어나 새 분석 요청은 수행하지 않습니다. 감사 로그 메뉴는 별도로 유지됩니다.

알림은 `/api/notifications`의 본인 목록과 SSE를 연결합니다. 상단 종 버튼에서 목록을 펼쳐 읽음 처리와 사건 상세를 열 수 있습니다. 계정 메뉴에서는 현재 백엔드가 제공하는 조회와 권한·상태 수정만 지원합니다.

알림 목록은 최근 20건이며 배지는 그중 읽지 않은 개수입니다. 관리자도 본인 알림만 수신합니다. 일반 사용자 대시보드의 최근 알림은 같은 구독과 읽음 상태를 재사용합니다.

## 검사와 포맷

아래 명령은 `frontend/`에서 실행합니다.

```powershell
npm run build          # 현재 서비스 프로덕션 빌드
npm run check          # 서비스 동작 검사
npm run check:app      # 실제 서비스 컴포넌트의 모의 API 동작 검사
npm test               # 비전 요청·카메라 등록 단위 검사
node --test src/features/discord/discord.test.mjs # Discord 전용 검사 (별도 실행)
npm run format         # 실제 서비스 코드와 동작 검사 스크립트 포맷
npm run format:check   # 포맷 일치 여부 확인
```

서비스 검사에는 로그인·가입·세션 복원과 만료, 프로필 수정, 피드백 검색·CRUD·관리자 처리, 사용자 권한·상태 관리, 메뉴 재클릭·요청 취소, 카메라 공유 상태, 사용자·관리자 운영현황, 관리자 사진·분석 조회, 알림·Discord 화면 연결을 포함합니다. API는 모의 응답으로 확인합니다.

Discord 전용 검사는 기본 `npm test`에 포함되지 않습니다. 현재 Windows에서는 테스트 코드의 URL 경로 변환 문제로 실행이 실패할 수 있습니다. 이는 별도 수정 대상이며 서비스 실행에는 영향을 주지 않습니다. Discord 개발용 미리보기는 개발 서버의 `/src/features/discord/preview.html`에서 열 수 있고, 실제 로그인·DM을 보내지 않습니다.

검사는 모의 서버 응답과 React Test Renderer를 사용합니다. 실제 Supabase·백엔드 연결과 브라우저 레이아웃 검증은 별도 확인이 필요합니다.
